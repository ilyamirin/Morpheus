Matrix · Rust · Federated Commerce

Morpheus превращает независимые marketplace-серверы в доверенную федерацию.

Каждый instance владеет своим каталогом, allowlist, политиками, Postgres-хранилищем и API. Matrix/Synapse доставляет проверяемые события, Morpheus валидирует протокол, сохраняет raw timeline и строит локальные projections для admin, seller и buyer UI.

Protocol principles

2. Принципы работы

Локальная автономия

Morpheus не требует центрального marketplace. Каждый сервер сам решает, каким instance доверять, какие политики принимать и какие projections показывать пользователям.

Allowlist вместо глобального поиска

Federation строится вокруг локального allowlist. Если `fashion.example` доверен на `books.example`, books может принимать и индексировать его catalog/order события.

Matrix как транспорт

Matrix/Synapse отвечает за room membership, federation transport и timeline. Morpheus определяет только marketplace namespace, validation rules и state machines.

Replayable state

Raw Matrix events сохраняются, accepted events становятся источником projections. Order lifecycle можно переиграть и проверить заново без доверия к текущей таблице projection.

Секреты вне Matrix

Payment secrets, bearer URLs, license keys, credentials, файлы и delivery artifacts не передаются в `io.marketplace.*`. В событиях остаются только ссылки и evidence metadata.

Strict protocol envelope

Все события несут `protocol`, `protocol_version`, `protocol_event_id`, `created_at`, `issuer` и typed `body`. Unknown critical fields отклоняются.

В mini dev окружении эти принципы можно проверить руками: seller publication меняет catalog projection, buyer order creation создаёт Matrix order room на backend-е, seller lifecycle публикует события в эту room, а admin UI показывает итоговые counters и validation stream. Подробная инструкция: Developer Setup.

Runtime architecture

3. Архитектура сервера

Production surface состоит из Axum backend, Matrix Application Service integration, Postgres projections и CLI/operator tooling. Внутри workspace протокол и state machines вынесены в pure Rust crates, чтобы HTTP, SQL и Matrix не смешивались с правилами валидации.

Ключевой boundary: `morpheus-core` и `morpheus-protocol` не зависят от Axum, SQLx, Tokio networking или Synapse.
01HTTP APIadmin / seller / buyer
02PublisherMatrix client API
03Synapse AStransactions endpoint
04Validatorprotocol + context
05Storeraw events + projections
В Docker E2E этот pipeline повторяется три раза: `books.example`, `cases.example`, `fashion.example` имеют разные Postgres, Synapse и Morpheus runtime. nginx federation proxies дают Synapse reachable TLS endpoints на `:8448`, а Morpheus servers доступны разработчику на `18081`, `18082`, `18083`.

Role journeys

4. Как роли проходят через protocol flow

A

Seller публикует каталог

  1. Seller announces actor через `/api/v1/seller/announce`.
  2. Создаёт или обновляет product и offer.
  3. Morpheus пишет protocol event в catalog room.
  4. Synapse возвращает event через AS transaction.
  5. Backend валидирует событие и обновляет catalog projection.
B

Buyer создаёт order

  1. Buyer выбирает offer из локальной catalog projection.
  2. Backend создаёт private order room сам, без client-supplied room id.
  3. В room приглашаются seller и arbiter AS users.
  4. После join backend публикует `customer.bound` и `order.created`.
  5. Ответ `202 Accepted` содержит реальный Matrix `room_id`.
C

Seller закрывает lifecycle

  1. Seller backend lazily joins order room перед publish.
  2. Публикует `order.accepted`.
  3. Создаёт payment intent, затем authorized/captured.
  4. Публикует entitlement grant.
  5. Завершает order через `order.completed`.
Практический путь товара описан отдельно для UI, CLI и HTTP API: UI journey, CLI journey, API journey.

Configuration

6. Настройка instance

Один Morpheus server описывается TOML-конфигом. Для локального запуска используется `config/local.toml`; для federation E2E - `config/e2e/books.toml`, `config/e2e/cases.toml`, `config/e2e/fashion.toml`.

Секция Назначение Важные поля
[instance] Идентичность marketplace instance и protocol capabilities. instance_id, matrix_server_name, catalog_room_alias, order_room_alias_prefix
[appservice] Связь Morpheus с Synapse Application Service. homeserver_url, sender_localpart, homeserver_token, appservice_token
[database] Runtime storage для raw events и projections. url
[admin] / [auth] Bind address и env names для bearer tokens. bind, MORPHEUS_ADMIN_TOKEN, MORPHEUS_SELLER_TOKEN, MORPHEUS_BUYER_TOKEN
[[allowlist.instances]] Локальная trust policy для remote instances. status, capabilities, catalog_room_alias, morpheus_url 
cargo run -p morpheus-cli -- config validate --config config/local.toml
cargo run -p morpheus-cli -- synapse registration \
  --config config/local.toml \
  --out .local/synapse/morpheus-registration.yaml

Single server

7. Запуск одного локального сервера

Postgres и pgweb

docker compose up -d postgres pgweb

Postgres доступен на `localhost:5432`, pgweb - на `http://localhost:8081`.

Synapse bootstrap

mkdir -p .local/synapse
docker run --rm \
  -v "$PWD/.local/synapse:/data" \
  -e SYNAPSE_SERVER_NAME=localhost \
  -e SYNAPSE_REPORT_STATS=no \
  matrixdotorg/synapse:latest generate

После генерации добавьте registration file в `.local/synapse/homeserver.yaml`.

Database migration

cargo run -p morpheus-cli -- db migrate \
  --database-url postgres://morpheus:morpheus@localhost:5432/morpheus \
  --database-kind postgres

Server process

MORPHEUS_ADMIN_TOKEN=admin-token \
MORPHEUS_SELLER_TOKEN=seller-token \
MORPHEUS_BUYER_TOKEN=buyer-token \
cargo run -p morpheus-server -- --config config/local.toml

После старта API и PoC UI доступны на http://127.0.0.1:8080.

Federated E2E

8. Запуск трёх federated серверов

E2E stack поднимает три независимых marketplace instances: `books.example`, `cases.example`, `fashion.example`. У каждого свой Morpheus server, Synapse homeserver и Postgres database. Federation endpoints обслуживаются nginx TLS proxy на `8448` с local CA, которому доверяют все три Synapse.

Подробный runbook по контейнерам, UI кабинетам, CLI и API находится на странице Developer Setup.

books.exampleMorpheus: 18081Synapse: 18008
cases.exampleMorpheus: 18082Synapse: 18009
fashion.exampleMorpheus: 18083Synapse: 18010
make e2e-three-synapse
make e2e-three-synapse-down
E2E smoke сначала проверяет Matrix federation: books создаёт private room, invites cases/fashion AS users, remote users join-ятся через свои homeservers, fashion отправляет test event в federated room.

Troubleshooting

11. Частые проблемы

Synapse не отправляет transactions в Morpheus

Проверьте `app_service_config_files`, `homeserver_token`, `url` в registration YAML и доступность Morpheus container hostname из Synapse container.

Order create возвращает 502

Это ожидаемый hard failure, если Synapse не смог создать federated room с invites. Проверьте federation DNS aliases, nginx TLS proxy, CA trust и reachability `:8448`.

Seller не видит remote order

Проверьте, что seller AS user был приглашён и join прошёл. В backend order create ожидает join invited users перед публикацией order events, чтобы timeline дошёл до remote server.

Remote catalog не появился мгновенно

На текущем этапе trusted remote catalog visibility строится через Morpheus peer API indexer. Проверьте allowlist entry, `morpheus_url`, network reachability и catalog rebuild.
