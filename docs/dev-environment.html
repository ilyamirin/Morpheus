Purpose

2. Что это за developer setup

`make e2e-three-synapse` поднимает локальную federation-сеть, которая не является чистым mock-ом: seller writes проходят через Morpheus API, Matrix publisher, Synapse, Application Service ingest, protocol validation и Postgres projections. При этом payment adapter в PoC остаётся `mock`, а remote catalog visibility сейчас строится trusted Morpheus peer indexer-ом по API. Order flow использует настоящие backend-owned Matrix order rooms.

Три независимых instance

`books.example`, `cases.example`, `fashion.example` имеют разные configs, DB, Synapse homeserver и Morpheus server.

Один Docker network

Контейнеры общаются по service DNS. Federation domains резолвятся не в Synapse, а в nginx TLS proxy.

Проверяемый seed

Скрипт seed-ит 14 sellers, 28 products, 28 offers и один cross-instance completed order.

Реальные UI/API/CLI

Один и тот же backend доступен через `/ui/*`, HTTP endpoints и `morpheus` CLI.

Runbook

3. Запуск, проверка и остановка

Запустить всю federation-сеть

make e2e-three-synapse

Команда генерирует Synapse configs и local CA, собирает Morpheus image, поднимает контейнеры, ждёт readiness, проверяет federation smoke, запускает demo seed и сверяет projection counts.

Быстро проверить, что сервисы живы

curl -fsS http://127.0.0.1:18081/readyz
curl -fsS http://127.0.0.1:18082/readyz
curl -fsS http://127.0.0.1:18083/readyz

Каждый endpoint должен вернуть `{"status":"ready"}`.

Остановить и очистить данные E2E

make e2e-three-synapse-down

Это делает `docker compose -f docker-compose.e2e.yml down -v` и удаляет Synapse sqlite файлы из `.local/e2e/synapse-*`. Docker build cache при этом не должен удаляться.

Последняя строка успешного запуска: `three-synapse e2e ok`. Перед ней должны быть `federation smoke ok (...)` и `demo seed ok`.

Browser surfaces

6. UI кабинеты: куда ходить и что проверять

Все UI используют bearer token из input-а и хранят его только в `localStorage`. Для E2E placeholders: `admin-token`, `seller-token`, `buyer-token`. UI не выдаёт secrets с backend-а.

Роль URL Token Что проверить
Admin /ui/admin admin-token Health, readiness, config JSON, allowlist, catalog/order/payment/entitlement counters, validation stream.
Seller /ui/seller seller-token Storefront cards, quick add listing, seller orders, Accept -> Intent -> Capture -> Grant -> Complete.
Buyer /ui/buyer buyer-token 28 seeded offers, unique product images, checkout sheet, order tracking, cancel while valid.

UI customer journey

7. Путь товара в UI: публикация, покупка, lifecycle, снятие

S

Seller публикует товар

  1. Открыть http://127.0.0.1:18081/ui/seller.
  2. Проверить token `seller-token` или ввести свой seller bearer.
  3. Нажать `Activate seller`: UI отправляет `POST /api/v1/seller/announce`.
  4. Заполнить title/category и нажать `Save product`: `POST /api/v1/seller/products`.
  5. Заполнить price/currency и нажать `Publish listing`: `POST /api/v1/seller/offers`.
  6. После projection refresh карточка появляется в storefront и в buyer catalog.
B

Buyer покупает

  1. Открыть http://127.0.0.1:18081/ui/buyer.
  2. Нажать `Refresh catalog`; UI читает sellers/products/offers projections.
  3. Нажать `Buy` на offer. Checkout получает offer id, amount и currency из projection.
  4. Нажать `Create order`: `POST /api/v1/buyer/orders` без editable `room_id`.
  5. Backend создаёт private Matrix order room, приглашает seller/arbiter AS users и возвращает реальный `room_id`.
  6. До прихода AS projection UI показывает submitted/pending state и автоматически обновляет orders.
  7. Buyer orders panel показывает created/accepted/payment/entitlement/completed timeline.
L

Seller закрывает lifecycle

  1. Открыть seller UI того instance, которому принадлежит seller id.
  2. Нажать `Refresh orders`: `GET /api/v1/seller/orders`.
  3. Нажать `Accept`: seller backend lazily join-ится в order room перед publish.
  4. Нажать `Intent`, затем `Capture`: публикуются payment intent/authorized/captured events.
  5. Нажать `Grant`: entitlement grant event фиксирует внешний доступ или license ref.
  6. Нажать `Complete`: order становится completed, admin counters обновляются.
W

Seller снимает offer с продажи

  1. В текущем PoC UI отдельной кнопки withdraw нет: снятие выполняется через CLI/API.
  2. После `seller offer withdraw` вернуться в /ui/buyer и нажать `Refresh catalog`.
  3. Offer должен исчезнуть из discovery для новых покупателей.
  4. Если buyer успел открыть stale карточку и нажал `Create order`, backend возвращает `409 OFFER_WITHDRAWN`.
  5. Открыть /ui/admin, нажать refresh/rebuild при необходимости и проверить catalog counters/events.
  6. Уже созданные orders не переписываются: они продолжают lifecycle по зафиксированным terms/hash.
  7. Это важное разделение: withdrawal влияет на будущий catalog discovery, а не отменяет прошлые сделки.
Cancellation и withdrawal имеют разные смыслы. Buyer cancel валиден только до payment/entitlement/completion. Seller offer withdraw снимает offer из будущего catalog discovery, но уже созданные orders продолжают жить по зафиксированным terms/hash. В UI это проверяется как наблюдаемый результат: после CLI/API withdraw buyer catalog больше не показывает снятый offer.
Remote catalog indexer работает устойчиво к временной недоступности trusted peer. Если peer API не отвечает, sync report помечается как `cached` с кодом `REMOTE_CATALOG_UNAVAILABLE`, а buyer discovery продолжает показывать последние успешно принятые projections вместо пустого каталога.

Runtime internals

10. Как это работает внутри

01UI / CLI / HTTP clientrole token + JSON request
02Morpheus APIactor scope, DTO validation, state prechecks
03Matrix publishercatalog room или backend-owned order room
04Synapse federationroom membership, remote invites, AS transactions
05Protocol validationenvelope, authority, event-specific body, lifecycle order
06Postgres projectionscatalog, orders, payments, entitlements, admin counters
Секреты не попадают в Matrix events: payment secrets, bearer URLs, credentials, license keys и delivery files остаются вне `io.marketplace.*`. В protocol событиях используются refs, hashes и evidence metadata.

Troubleshooting

11. Диагностика developer setup

Сборка Docker снова качает Rust deps

Первый build после cache-фича всё равно прогревает cache. Повторные build-и используют BuildKit cache mounts для Cargo registry/git/target. Cache сбрасывается `docker builder prune`, `docker system prune` или очисткой Docker Desktop.

Order create возвращает 502

Проверьте federation proxies, DNS aliases `books.example`, `cases.example`, `fashion.example`, TLS CA trust в Synapse и то, что remote AS users могут быть invited/joined.

Catalog не видит remote товары

Проверьте allowlist capabilities `catalog` и `indexing`, `morpheus_url` в config/e2e/*.toml, доступность peer Morpheus API из контейнера и `POST /admin/catalog/rebuild`.

UI показывает 401/403

401 обычно означает неверный bearer token для роли. 403 `ACTOR_FORBIDDEN` означает, что actor id не принадлежит local instance, например seller endpoint на books получил `seller:fashion.example:*`.
